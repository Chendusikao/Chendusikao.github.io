# AI 应用开发岗位作品集改版设计

## 目标

将现有 Hugo 个人站改为面向 AI 应用开发岗位招聘者的作品集。访问者应在首页快速理解作者的定位、技术能力、代表项目和联系方式，并能进一步查看每个项目的完整案例。

## 已确认的方向

- 目标岗位：AI 应用开发岗。
- 个人定位：能够独立完成需求梳理、AI 能力接入、前后端开发与部署上线的全栈型开发者。
- 站点展示约 3–4 个项目，首页展示精选项目并保留完整项目列表。
- 视觉方向：深海军蓝背景、荧光绿与青蓝色强调色；专业、克制的技术风，不采用拥挤的赛博朋克装饰。
- 写作内容作为持续学习与思考的辅助证明，不占据首页主视觉。

## 信息架构

### 首页

1. 顶部导航：首页、项目、关于、联系。
2. 首屏：`Chendusikao · AI 应用开发工程师` 定位、简洁自我介绍、能力标签，以及抽象 AI 工作流或数据图形。
3. 能力区：展示真实掌握的技术标签，例如 LLM、RAG、Agent、Python、后端、前端和部署。
4. 精选项目区：展示 3–4 张项目卡片。
5. 交付能力区：从需求、AI 集成、工程实现到部署上线的交付流程。
6. 联系区：GitHub、简历下载入口和邮箱。

### 项目列表与详情

- `/projects/` 展示全部项目。
- 每张卡片展示项目名称、要解决的问题、AI/技术方案、状态、技术标签以及 GitHub/演示链接。
- 每个项目详情页按“背景、方案、技术栈、职责、结果或当前进度”的顺序呈现。
- 项目资料不完整时明确标记“开发中”，不虚构功能、指标或技术栈。

## 内容模型

项目继续以 `content/projects/*.md` 管理。项目的 front matter 将统一包含标题、日期、状态、摘要、技术标签、GitHub 地址与可选的演示地址；正文按案例模板编写。新增项目时复制该模板即可，无需修改首页结构。

## 技术实现

- 保持 Hugo + GitHub Pages + GitHub Actions 部署链路。
- 使用自定义 Hugo 首页与项目列表模板，并配套站点级 CSS；不依赖后端、数据库或第三方登录服务。
- 在桌面与移动端均保持清晰的项目浏览和联系入口。
- 首页从项目内容读取信息，避免手工维护同一项目的多个副本。

## 质量要求

- 本地执行 Hugo 构建，确保没有模板或内容错误。
- 检查导航、GitHub 链接、项目详情页和移动端布局。
- 推送后确认 GitHub Actions 与 GitHub Pages 部署成功。
- 生成内容与展示信息只使用作者确认过的事实。

## 非目标

- 不在本次改版中开发登录、评论、数据库、实时行情或聊天功能。
- 不把当前项目伪装为已完成的 AI 产品。
